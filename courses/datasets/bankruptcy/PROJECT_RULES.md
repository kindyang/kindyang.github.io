## 1. 分析对象与预测目标

| 项 | 约定 |
|---|---|
| 观测单位 | **公司-样本**（台湾上市公司，1999–2009 年财务数据，合并为一张截面表） |
| 样本规模 | 6819 行 × 96 列（1 标签 + 95 个财务比率特征 X1–X95） |
| 预测目标 | **二分类**：预测公司是否破产（标签 `Bankrupt?`） |
| 输入 | X = 95 个财务比率（盈利能力、偿债、成长、周转、流动性等，含义见 DATA.md 第 3 节） |
| 输出 | 破产概率 P(破产) ∈ [0,1]，按概率与排名使用 |
| 应用场景 | 信贷风控、投资预警（事前预测，强调"不漏报破产"） |

- **规则 1.1**：所有分析、代码、报告均以"公司是否破产"为唯一预测目标，不得引入其他标注。
- **规则 1.2**：本任务只允许在 `claude_work/` 目录内创建/修改文件。

## 2. 标签口径（Bankrupt?）与不平衡处理

### 2.1 标签定义
- `Bankrupt?`：1 = 破产，0 = 未破产；破产定义依据台湾证券交易所业务规定（数据提供方口径）。
- 分布：0 → 6599（96.77%），1 → 220（3.23%），约 **1:30** 极度不平衡。

### 2.2 不平衡处理约定（三管齐下，缺一不可）
1. **划分侧**：随机划分必须 `stratify=y` 分层抽样，保证训练/验证/测试集中正类占比 ≈3.2%。
2. **模型侧**：基线模型启用 `class_weight='balanced'`（或 sklearn 等价参数）；若做重采样（如 SMOTE），**只允许在训练集内拟合/合成，严禁污染验证与测试集**。
3. **评估侧**：**禁止以 accuracy 作为主指标**（全预测 0 即有 96.77% 准确率）。主指标为 AUC、PR-AUC、F1，并附混淆矩阵。

### 2.3 基线对照
- 随机猜测：AUC ≈ 0.50，PR-AUC ≈ 正类占比 0.032。模型若未能明显超过该基线，视为无效。
- 报告 PR-AUC 时必须同时报告其"无技能基线"（正类占比），避免数字失真。
- 阈值选择：因正类仅 3.23%，默认 0.5 阈值不适配；按 F1/业务成本在验证集上选择阈值后在测试集报告。

## 3. 特征规则

- **规则 3.1（列名清洗）**：原始表头含前导空格（如 `' Bankrupt?'`），读入后统一 `strip()` 列名再做任何操作；后续脚本一律使用清洗后的列名。
- **规则 3.2（常量列删除）**：删除建模前唯一值 ≤ 1 的列（如 `one if net income was negative for the last two year zero otherwise`）。删除须记录：列名 + 版本号。
- **规则 3.3（0 分母处理）**：比率类特征分母可能为 0（总资产、净收入等），不得直接粗暴填 0 或逐行丢弃；策略为：分母为 0 的单元格置 NaN → 用训练集该列**中位数**填充。填充器只在训练集上拟合。
- **规则 3.4（离群值）**：财务比率长尾明显。对**线性模型**：winsorize（1%/99% 分位数截断）或 RobustScaler；对**树模型**：可容忍离群，注明即可。缩放/截断器一律在训练集上 fit。
- **规则 3.5（多重共线性）**：注意 ROA A/B/C 高度相关、负债率与净值/资产互为补数。线性模型（逻辑回归）**必须**检查相关性 |r|>0.9 的特征对并剔除其一（或使用 L1 正则 / VIF 检查）；树模型不强制。
- **规则 3.6（管线纪律）**：所有预处理（标准化、填充、winsorize、重采样）组成 sklearn `Pipeline`，只允许在**训练集**上 fit，一并 transform 验证/测试集。禁止在划分前做任何全局统计变换。
- **规则 3.7（特征变化留痕）**：每次删列、衍生列，在 exp_log 中记录版本 + 特征数变化（95 → n）。

## 4. 数据划分与防泄漏

### 4.1 数据时间属性说明
- 本数据为**截面数据**：1999–2009 年样本已合并为一张表，**无时间戳/年份字段**，不存在时间序列切分；统一采用**随机划分**。

### 4.2 统一划分方案（首次执行后固定，不可再变）
- train / valid / test = **70% / 15% / 15%**，`random_state = 42`，`stratify = y`（分层）。
- 固定保存划分结果（随机种子勿改）；除非项目规则更新，不得重新划分"重跑变好"。

### 4.3 防泄漏硬性规则
- 不得使用反事实信息；特征必须全部来自观测时点可得的信息。本数据集内无未来信息字段，**如需引入外部数据，禁止使用样本期（2009 年）之后的信息**。
- 不得在划分前计算全局均值/分位数/填充值。
- EDA 只允许在训练集上进行。
- 同一公司样本不得既在训练集又在测试集（本数据集每行为独立公司，无重复 ID，仍要检查重复特征行）。

## 5. 建模与评估约定

### 5.1 模型方案
| 优先级 | 模型 | 说明 |
|---|---|---|
| 基线 1 | 逻辑回归（`class_weight='balanced'`） | 线性基线，可解释 |
| 基线 2 | 随机森林 / GBDT（LightGBM 或 XGBoost 任选） | 树模型基线，处理非线性与交互 |
| 对照 | DummyClassifier（strategy='most_frequent'） | 报告必须包含，验证不平衡处理必要性 |
- 超参调优只在**验证集**上进行（GridSearch / RandomSearch，固定 5 折 CV，`random_state=42`）。

### 5.2 评估指标（按优先级）
| 指标 | 用途 |
|---|---|
| AUC（ROC） | 整体排序能力，首要指标 |
| PR-AUC（含正类占比基线） | 类别不平衡下的精细指标 |
| F1（在验证集选阈值后） | 阈值化决策指标 |
| Recall（召回率） | 业务关键：漏报破产代价大 |
| Brier Score | 概率校准质量 |

### 5.3 随机性与纪律
- 全局 `random_state = 42`；一切随机操作（shuffle、CV、SMOTE）显式传种子。
- **测试集只允许使用一次**：最终确定的唯一模型，在测试集上评估一次并锁定报告数字；**测试集结果不得返回去改模型**。
- 每次实验在 `exp_log.md` 记录：版本号、模型、特征版本、调参范围、指标结果、时间。
