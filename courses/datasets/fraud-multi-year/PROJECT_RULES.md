## 2. 文件命名规则

### 2.1 通用格式

```
<对象>_<类型>_v<N>.<扩展名>
```

### 2.2 分类命名表

| 类别 | 命名模板 | 示例 | 版本号 |
|---|---|---|---|
| 脚本 | `<序号>_<动作>.py` | `01_build_label.py` | ❌ 不需要 |
| 中间数据 | `<对象>.csv/.parquet` | `fraud_label.csv` | ❌ 不需要 |
| 最终数据 | `<对象>_v<N>.csv` | `panel_ml_v1.csv` | ✅ 需要 |
| 模型结果 | `<指标名>_v<N>.csv` | `model_results_v1.csv` | ✅ 需要 |
| 图表 | `<图名>_v<N>.png` | `eval_v1.png` | ✅ 需要 |
| 报告 | `<序号>_<主题>.md` | `01_数据质量报告.md` | ❌ 不需要 |

### 2.3 ★ 允许覆盖 vs 禁止覆盖

> **判断标准（一句话）**：删掉之后，能不能用代码原样还原？能 → 允许覆盖；不能 → 必须留版本。

| 场景 | 处理 | 理由 |
|---|---|---|
| 重跑 `01_build_label.py` 产出 `fraud_label.csv` | ✅ **覆盖** | 同输入必得同输出，无信息损失 |
| 调整超参后产出新的模型结果 | ❌ **新建 v2** | v1 的调参结论是决策依据，丢了无法还原 |
| 修正 bug 后重跑中间数据 | ✅ **覆盖** | 修正后的才是对的 |
| 换了特征集生成新面板 | ❌ **新建 v2** | 不同特征集是不同实验，需要对比 |
| 图表改配色/样式 | ✅ **覆盖同名** | 同一版本的打磨，非新实验 |

### 2.4 严禁出现的文件名 🚫

```
❌ final.xlsx   ❌ 最终版.xlsx   ❌ 最终真的最终.xlsx
❌ 新建文件夹 (2)  ❌ data_new.csv  ❌ 未命名.py
❌ Untitled-1.ipynb
```

## 3. 迭代与版本控制

### 3.1 版本号递增规则

```
v1   → 首次产出
v2   → 换了方法/数据/口径（结果与 v1 不可比）
v2.1 → 同方法下的小修（结果可比，通常是修 bug）
```

### 3.2 什么时候必须保留旧版本

1. 更换了**标签口径**（如 V1 六类 → V2 含 P2515）/ 特征集 / 样本区间
2. 更换了模型算法或超参数
3. 结果将被写入报告（报告引用的数据必须可回溯）
4. 已经给别人看过的结果

### 3.3 避免文件堆积：单一入口原则

```
results/

    └── 2026-10-16_v2_换了舞弊口径/
```
归档目录命名：`<日期>_<版本>_<一句话说明>`。

## 4. 数据与磁盘管理

### 4.1 大文件处理（>100MB）

| 文件 | 大小 | 处理 |
|---|---|---|
| `FS_Combas.xlsx`（478MB，154 列） | 特大 | 留在原始下载目录，**不复制进项目**；openpyxl read_only + `reset_dimensions()` 流式读（实操 587 秒全列） |
| `FS_Comins.xlsx`（255MB，81 列） | 大 | 同上（实操 315 秒全列） |
| `STK_Violation_Main.xlsx`（14.6MB） | 小 | 可以直接 pandas 读，但要过滤 2 行表头残留 |
| 中间数据 | 中 | 建议存 parquet/csv+zip，压缩后约 1/3 体积 |

### 4.2 中间产物可以删吗？

先问一句：**重跑生成它的脚本要多久？**

- < 5 分钟 → 可以删，需要时重跑
- \> 30 分钟 → 压缩归档，不要直接删（大表全列扫描一次约 10 分钟）
- 依赖手工修正 → **绝对不能删**

### 4.3 绝对不能删的文件

1. `raw/` 下的所有原始数据（重新下载要走 CSMAR，且版本可能变化）
2. 字段字典（财务两表的字典**在 zip 内**，zip 更不能删）
3. 任何包含**人工判断**的文件（报告、口径说明、决策记录）
4. `DATA.md` / `PROJECT_RULES.md`

### 5.1 写文件之前

1. **先读 `DATA.md`**——确认目标字段、口径、陷阱已记录在案
2. **先查本文件**——确认目标路径、命名、是否允许覆盖
3. 若目标文件存在且属于"禁止覆盖"类 → 自动递增版本号
4. 写完立即打印：文件路径、行数、关键统计

### 5.2 删除权限

- AI **不得删除** `raw/`、`results/`、`reports/` 下的任何文件
- `work/` 下的中间产物：重生成前可以覆盖，但不主动删除
- 任何批量删除操作（>10 个文件）必须先列出清单，经确认后执行

### 5.3 遇到规则未覆盖的情况

不要自行发挥，停下来向用户报告：
```
规则未覆盖的情况：
- 场景：<描述>
- 我的建议：<方案>
- 需要你确认：<具体问题>
```

### 5.4 每步结束必须留下什么

| 动作 | 必须留下 |
|---|---|
| 数据处理 | 处理前后的行数对比（增删了多少行、为什么） |
| 建模 | 模型配置 + 数据版本号（哪个 panel 训的） |
| 判断/决策 | 一句话理由（为什么这么做），写进报告或代码注释 |

## 7. 分析对象与预测目标

### 7.1 预测对象

| 项 | 定义 |
|---|---|
| 研究问题 | 用上年财务数据，预测该公司当年是否发生**财务舞弊** |
| 观测单位 | **公司-年**（一家公司一年一行） |
| 任务类型 | 二分类 |
| 正样本 | 该年发生财务舞弊的公司-年（口径 §8.2） |
| 负样本 | 该年未发生财务舞弊的公司-年 |

### 7.2 概念辨析

| 概念 | 含义 | 本项目？ |
|---|---|---|
| **财务舞弊** | 财务报表的虚假陈述：虚构利润、虚列资产、虚假记载等 | ✅ 就是这个 |
| 财务困境 | 经营失败/偿债困难（ST、资不抵债） | ❌ 舞弊≠困境 |
| 退市 | 被交易所摘牌 | ❌ 退市是**结果**，不是行为 |

### 7.3 样本框约束（沿用参考文档裁定，保留可改）

- 金融业：**保留但标注**，稳健性检验时剔除试试
- ST：**保留**——ST 恰是舞弊高发群体，剔除引入选择偏差
- 数据缺失严重的公司-年：特征非空数 < 5 的剔除

### 8.3 严重舞弊子标签

is_serious = 1  当且仅当  该公司-年中含 P2501 或 P2502   （实测 1,183 公司-年）

### 8.4 标签年份：ViolationYear，不是 DeclareDate ★★★

**规则**：标签年份 = `ViolationYear`（违规实际发生年）。

**依据（实测）**：13,418 条单年度记录 —— 公告比违规平均晚 0.94 年（中位数 1 年，19.3% 晚 2 年+）。
用 `DeclareDate` 打标签 = 把"被查处时点"当"舞弊时点"，特征混入败露后的业绩崩塌 = **用结果预测结果**。

**检查**：标签构建后随机抽 5 个正样本，对照原始违规表人工核对。

### 8.5 负样本与 merge 方向 ★★★

**规则**：财务面板 **left join** 标签；缺失填 0。

```python
rate = panel["is_fraud"].mean()
assert rate < 0.99, f"舞弊率 {rate:.2%} = 100%！join 方向错了(inner)，立即回退"
if not (0.05 <= rate <= 0.25):
    print(f"⚠ 舞弊率 {rate:.2%} 超出实测区间 5%-25%，请复核口径")   # 软警告
```

> 实测参考：2007–2021 舞弊率 ≈ **15.0%**（上界）；全区间 ≈ 13.0%。

## 9. 时间点与预测窗口 ★★★

### 9.1 时间轴

```
      t-1 年                    t 年
 ┌──────────────┐         ┌──────────────┐
 │  财务报表      │         │  舞弊行为发生   │
 │ (12-31年报)   │         │ (ViolationYear│
 │              │         │   = t)        │
 └──────┬───────┘         └──────────────┘
        ▼                        ▼
  预测时点: t 年 4 月 30 日前    标签: is_fraud = 1
```

**一句话**：用 **t-1 年年报**的全部财务特征，预测 **t 年**是否发生舞弊。

### 9.2 预测时点的可得性约束

| 信息 | 可得？ |
|---|---|
| t-1 年报的全部财务数据 | ✅（已披露） |
| t-1 年之前所有年份的财务数据 | ✅ |
| t 年任何财务数据 | ❌（还没披露） |
| t 年的处罚公告 | ❌（舞弊都还没发生） |
| 违规表的处罚金额/方式 | ❌（这是 t 年之后的事） |

**规则**：任何特征必须能在预测时点之前公开获得。

### 9.3 特征-标签对齐的代码实现

```python
fin["Year"] = fin["Year"] + 1   # 特征年 +1 = 预测目标年
panel = pd.merge(fin, label, on=["Stkcd","Year"], how="left")
```

**检查**：merge 后抽一家已知舞弊公司，舞弊年是 t → 该行财务数据必须是 t-1 年 12-31 的。手工核对一次。

### 9.4 披露时滞的诚实声明

t-1 年报在 t 年 1–4 月才陆续披露，本项目简化为"年度对齐"，**必须在报告中声明**。

## 10. 特征构造规则

### 10.1 允许的特征来源

| 来源 | 允许 | 说明 |
|---|---|---|
| t-1 年资产负债表/利润表（年报 A+12-31） | ✅ | 主要来源 |
| t-2 及更早年份（增长率、趋势） | ✅ | 预测时点可得 |
| t 年任何财务数据 | ❌ | 时间泄漏 |
| 违规表的任何字段 | ❌ | 标签泄漏（见 §11.2 黑名单） |
| 处罚金额、处罚方式 | ❌ | 舞弊的**结果** |
| 财务表的 `IfCorrect` / `DeclareDate`（差错更正信息） | ❌ | 事后信息，见 §11.5 |

### 10.2 数值处理规则

| 情形 | 规则 | 检查方法 |
|---|---|---|
| 比率分母为 0 | 分母 `replace(0, np.nan)` | `np.isinf(X).sum() == 0` |
| 增长率 | 按 `(Stkcd)` groupby 后 pct_change | 抽查某公司首年增长率为 NaN |
| 极端值 | 缩尾 1%/99% 分位 | 分位数**只用训练集**计算 |
| 缺失 | 中位数填补 | 填补器 fit 只出现在 train 上 |
| 财务报表筛选 | `Typrep=="A"` **且** `Accper[5:10]=="12-31"` | 必须排除 `01-01` 年初数行 |

### 10.3 特征黑名单（禁止用作特征）

```
ViolationID / Symbol / ViolationType / ViolationTypeID / ViolationYear /
IsViolated / Activity / Law / DisposalDate / DeclareDate(违规表) /
Penalty / SumPenalty / PunishmentType / PunishmentTypeID / PunishmentMeasure
文案类: FileName / DocumentNumber / Promulgator / Supervisor / CoFullName
财务表: IfCorrect / DeclareDate_fin（差错更正信息，事后性）
```

### 10.4 特征质量门槛

- 单特征缺失率 > 50% → 考虑删除或转哑变量（如研发费用 2016 前制度性缺失）
- 相关系数 > 0.95 → 保留经济含义更清晰的一个
- 每个特征必须能写出一句话经济含义（写不出来的 = 不知道在算什么，删）

## 11. 数据泄漏防护 ★★★

**五种泄漏，每种配一个必做检查**：

### 11.1 时间泄漏

> 特征晚于标签（或使用了预测时点之后才公开的信息）

**本数据特有的三个时间泄漏源**：
1. 用 `DeclareDate` 打标签（数据事实：平均滞后 0.94 年）❌
2. `Accper=01-01` 年初数行混入年报（部分为差错更正后的**事后数值**）❌
3. 财务表的 `IfCorrect`/`DeclareDate`（差错更正披露日期在报表期之后，且最长 65 字符多值）❌

**检查**：对每个特征列，回答"最早什么时候能拿到？"答不上来的默认有泄漏嫌疑。

### 11.2 标签泄漏

> 特征里混入了结果变量的变体

**检查**：特征名单 ∩ §10.3 黑名单 = ∅。代码实现：
```python
assert not (set(feat_cols) & set(BLACKLIST)), "特征含黑名单字段！"
```

### 11.3 预处理泄漏

> 标准化/填补/缩尾用了全样本统计量

**检查**：搜索代码里的 `fit`，确认所有 `fit` 只发生在训练集上。

### 11.4 划分泄漏

> train/test 切分方式与真实预测场景不符

**检查**：代码里不得出现 `train_test_split(shuffle=True)`；划分条件必须是 `Year`（时间）。

### 11.5 ★ merge 专项检查（每次 merge 标签后必做）

```python
sample = panel[panel.is_fraud == 1].head(5)
for _, r in sample.iterrows():
    feat_year = r["Year"] - 1
    print(f"{r['Stkcd']}: 标签年={r['Year']}, 特征来自{feat_year}年报")
# 人工核对: 特征年 == 标签年 - 1；若"特征年 ≥ 标签年"= 时间对齐错了
```

## 12. 训练/测试划分规则

### 12.1 划分方案（基于实测面板规模：Typrep=A 且 12-31，共 81,837 行）

| 集合 | 年份 | 实测行数 | 实测正样本(V1 上界) | 实测舞弊率 | 用途 |
|---|---|---|---|---|---|
| 训练集 | 2007–2017 | 28,310 | 3,697 | 13.1% | 拟合参数 |
| 验证集 | 2018–2019 | 8,065 | 1,577 | 19.6% | 调超参、选模型 |
| 测试集 | 2020–2021 | 9,601 | 1,643 | 17.1% | **最终评估，只用一次** |
| 未使用尾部 | 2022–2025 | 21,777 | — | 右截断不完整 | 仅可作外推观察，不训练 |

> 【待决策】年份切点可按项目时长调整，但**必须保持时间顺序**。
> 【待决策】样本终点若改 2022（面板 +5,279 行），需在报告中声明更严重的右截断。

### 12.2 为什么禁止随机划分

财务数据强自相关：今年舞弊的公司明年大概率继续舞弊。随机打乱会把同一家公司相邻两年拆进 train/test —— 模型靠"记住这家公司"就能在 test 上得高分，这不是预测，是作弊。

**检查**：`(Stkcd, Year)` 对在 train/test 间不得有交集：
```python
assert len(set(zip(train.Stkcd, train.Year)) &
           set(zip(test.Stkcd, test.Year))) == 0
```

### 12.3 类别不平衡处理规则

- **禁止** `class_weight='balanced'`（会毁掉概率校准）
- 允许：正常训练 + 预测后按 top-k 分位圈高风险名单
- 评估必看：ROC-AUC、PR-AUC、召回率、**Brier + 校准曲线**

### 12.4 其他提前约束

| 问题 | 规则 |
|---|---|
| 样本起点 | 2007（新会计准则实施，之前科目不可比） |
| 样本终点 | 2021（右截断实证见 DATA.md §3.6，报告须声明） |
| 模型选择 | 基线 Logistic + 树模型（RF/XGB）；不追新模型 |
| 随机种子 | 全部固定 `random_state=42`，写进脚本 |
| 结果报告 | 训练/验证/测试三个数字一起报，禁止只报测试集 |
| 诚实条款 | 测试 AUC > 0.85 视为泄漏警报，先排查再相信 |
