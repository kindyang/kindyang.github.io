|---|---|

| 编码 / 分隔符 | `utf-8-sig` / `,`（已探测确认） |
| 形状 | **4943 行 × 363 列** |
| 说明行 / 脚注行 | **无**。首行即表头，末尾仍是正常数据行；完全重复行 = 0 |
| dtype 分布 | `float64` 353 列、`int64` 7 列、`object` 3 列（共 360 数值列） |
| 3 个 object 列 | `REPORT_TYPE`='A'、`ACCOUTING_STANDARDS`='CHAS_2007'、`CURRENCY_CD`='CNY'，**全部为常数** |

### 2.2 观测粒度（务必先理解）

- **4943 行 = 3297 家公司的 1~2 条观测**：1651 家公司出现 1 次，1646 家出现 2 次。
- `END_DATE` 只有两个取值 `1 / 2`（≈ 一年内的两个报告观测/两个年度口径）；`END_DATE_REP` 取值 `1~5`。
- 所有行 `REPORT_TYPE='A'`、`FISCAL_PERIOD=12`、`MERGED_FLAG=1` → **单年份、年度、合并报表**截面数据。
- **含义**：同一公司可能有 2 行进入数据，**行之间不独立**（这是防泄漏的关键，见 PROJECT_RULES）。

### 2.3 字段分组（按列序，语义分块）

### 2.4 缺失情况

| 指标 | 值 |
|---|---|
| 全表单元格缺失率 | **56.91%** |
| 无缺失列 | 17 / 363 |
| **100% 缺失列** | 4 列：`QUIT_CONCERN_NI`、`OTH_GAIN`、`ASSETS_DISP_GAIN`、`GOING_CONCERN_NI` |
| 高缺失（≥98%）列 | 约 25 列，集中在**保险/银行/证券等金融专属科目**（`INSUR_RESER`、`RESER_INSUR_CONTR`、`PREM_*`、`REINSUR_*`、`POLICY_DIV_PAYT`、`PREFERRED_STOCK_*`、`PERPETUAL_BOND_*` 等） |
| 缺失率 Top30 | 见 `explore_fraud1_output.txt` 第 432–462 行 |

**原因解释**：缺失是**结构性（行业性）**的，而非随机——金融业科目对非金融企业天然为空。因此"高缺失"本身携带行业信息，处理时需谨慎（见 PROJECT_RULES 特征规则）。

### 2.5 常数与近常数列

- `nunique <= 1` 的数值列共 7 个：`FISCAL_PERIOD`(恒 12)、`MERGED_FLAG`(恒 1)、`ACCRUED_EXP`，以及 4 个全空列。
- 3 个 object 列（`REPORT_TYPE`/`ACCOUTING_STANDARDS`/`CURRENCY_CD`）也均为常数。
- → 这些列**对建模零信息量**，应剔除。

### 2.6 异常值粗查

- `±inf` 值：**0 个**（数据干净，无无穷）。
- `|值| > 1e12` 的单元格：**216 个，涉及 33 列**，集中在 `T_ASSETS`、`T_LIAB`、`T_LIAB_EQUITY`、`DEPOS`、`DISBUR_LA` 等——多为**大型银行/保险公司的真实巨额资产**，属**语义正常但量纲极端**，不是录入错误。
- 比率列存在极端离群：如 `ASSET_LIAB_RATIO` 全样本 max=**498966.16**、`ROE` min=**-18839.23**、`REVENUE_YOY` max=**10706.56** → 存在分母趋零导致的比率爆炸（见陷阱 T4）。

### 2.7 日期/期数列的编码陷阱

以下列**已被解析为数值**，不是日期字符串，含义特殊：

| 列 | 取值 | 解释 |
|---|---|---|
| `ACT_PUBTIME` / `PUBLISH_DATE` | 2,3,4,5,6,7 | 披露**月份**（3 月最多 = 2903 行，符合年报密集披露期） |
| `END_DATE_REP` | 1,2,3,4,5 | 报告截止期编号 |
| `END_DATE` | 1,2 | 同一公司的两个观测标识 |

> ⚠️ 这些列**不可当连续数值特征**（例如不能认为"3 > 2 有大小含义"），应作分类/分组键使用。

## 3. FLAG 标签定义与分布（核心）

### 3.1 定义

来自 `附件3.xlsx`（第 363 条）：**`FLAG` = 「是否在当年造假」**。

- `FLAG = 1` → 该公司当年**财务舞弊**（正类）
- `FLAG = 0` → 当年**未舞弊**（负类）
- `FLAG = NaN` → 标签缺失（1 行）

> 注意：`MERGED_FLAG` 是"合并/母公司"标志（恒为 1），**与标签 `FLAG` 完全无关**，勿混淆。

### 3.2 分布（极度不平衡）

| FLAG | 行数 | 占比 |
|---|---|---|
| 0（未舞弊） | 4914 | 99.43% |
| **1（舞弊）** | **28** | **0.57%** |
| NaN（缺失） | 1 | — |
| 合计 | 4943 | 100% |

- **不平衡比 ≈ 175.5 : 1**（0 类约为 1 类的 175 倍）。
- FLAG 为 `float64`（因含 NaN）。
- FLAG==1 的 28 行对应 **28 家不同公司**（无一家重复出现两次都被标记）。
- 公司级 FLAG 组合：`(0,1)` 22 家、`(1,)` 6 家、`(0,)` 1644 家、`(0,0)` 1624 家、`(NaN,)` 1 家。
  - 含义：**舞弊公司多为"两条观测中仅一条被标 1"**，标签处在"公司-观测"层级，但舞弊判定本质是**公司级**属性。

### 3.3 标签缺失行

- 唯一 FLAG=NaN 的行为 `TICKER_SYMBOL=2606132`，该行 `T_ASSETS=166,436,239.3` 但 `REVENUE`、`N_INCOME` 缺失 → 建议在建模时**剔除该行**。

## 7. 数据质量陷阱清单

| 编号 | 陷阱 | 事实 | 应对 |
|---|---|---|---|
| **T1** | 极不平衡标签 | 正类仅 28 / 4942（0.57%），比例 175:1 | 不可用 accuracy；用 PR-AUC/F1；分层抽样 |
| **T2** | 行不独立（同公司多观测） | 3297 家公司 → 4943 行，1646 家有 2 行 | 划分必须 **按公司分组**，否则泄漏 |
| **T3** | 结构性缺失 | 全表缺失 56.9%；金融专属科目缺失 98%+ | 缺失≠噪声，是行业信号；不要盲目填充 |
| **T4** | 比率爆炸（分母趋零） | `ASSET_LIAB_RATIO` max≈49.9万；`ROE` min≈-1.88万 | winsorize / 截尾 / 稳健缩放 |
| **T5** | 巨额原始金额 | 216 个单元格 >1e12（银行/保险真实值） | 金额列用比率或 log；不要混合行业量纲 |
