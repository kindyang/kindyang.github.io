> 数据事实索引：见 `DATA.md` §7「数据质量陷阱清单」（T1–T12），下文规则直接引用编号。

## 0. 建单人速读卡（30 秒版）

- 数据：4943 行 × 363 列，单年份截面，标签 **28 个正类**（0.57%）。
- 三座大山：**① 极度不平衡（T1）；② 同公司多观测需分组防泄漏（T2）；③ 56.9% 结构性缺失（T3）**。
- 三条铁律：**只读原始数据；只写 claude_work；划分必须按公司（TICKER_SYMBOL）分组（R4）。**
- 目标指标：**PR-AUC 为主，F1、正类 Recall 为辅（R6）**；禁止以 accuracy 论成败。
- 任何分析动作前：先跑基线、先看 DATA.md，再动模型。

## 1. 分析对象与预测目标（R1）

- **R1-1 分析单元**：每股观测 = 一家公司在某一观测期的一份财务报表（`TICKER_SYMBOL` + `END_DATE` 定位一行）。
- **R1-2 预测目标**：`FLAG=1` 表示"该公司当年舞弊"；输出为二分类概率 `P(舞弊)`。
- **R1-3 正负类口径**：正类 = FLAG==1 的 28 行；负类 = FLAG==0 的 4914 行；FLAG=NaN 的 1 行（ticker 2606132）**从所有训练/测试样本中剔除（T7）**。
- **R1-4 本期边界**：仅做单年份截面建模，**不做时间序列外推、不做跨期特征**（数据中无真实时间轴）。
- **R1-5 关于行业**：行业（附件1）是可选附加特征。因 94% 行可匹配、舞弊正类有 25% 无行业（T9），行业特征必须**支持缺失**（设 missing 类），不阻塞主流程。

## 2. 标签口径（R2）

- **R2-1 唯一标签列**：只允许使用 `附件2.csv` 的 `FLAG`（字典确认 = "是否在当年造假"）。**严禁将 `MERGED_FLAG`（合并标志）当作标签（T12）**。
- **R2-2 不重新造标签**：不依据任何字段派生/替换 FLAG。
- **R2-3 标签的层级问题（关键提醒）**：22 家公司"两条观测一条为 1、一条为 0"（见 DATA.md §3.2）。公式上按行建模，但**复盘时按公司归并**：只要某公司任一观测被预测为高风险，即视为"该公司被判风险"。评估时用**公司级**汇总指标作交差验证（给召回率、误报率两个视角）。
- **R2-4 阈值不预设**：默认 0.5 会被不平衡彻底摧毁；阈值由 PR 曲线/业务容忍度决定（R6-5）。

## 3. 特征规则（R3）

### 3.1 特征使用原则

- **R3-1 直接可用组**：比率/增长/周转类字段（列 219–361，如 `ROE`、`REVENUE_YOY`、`CURRENT_RATIO`、`DAYS_AR`）作为主体特征集。
- **R3-2 金额类（元）字段**：列 10–218 的原始金额列，**默认不直接进树模型以外的模型**；进树模型前做**行业内比率化或 log1p**（跨公司量纲差异巨大，T5）。建议优先使用数据集已有的比率衍生列，避免自己重复构造。
- **R3-3 保留元数据为分组/辅助键**：`TICKER_SYMBOL`、`END_DATE`、`END_DATE_REP`、`ACT_PUBTIME`、`PUBLISH_DATE` 只作分组/暴露变量，**不作特征**（编码陷阱，T8）。`FISCAL_PERIOD`、`MERGED_FLAG`、`REPORT_TYPE`、`ACCOUTING_STANDARDS`、`CURRENCY_CD` 为常数列，直接剔除（T6）。
- **R3-4 行业特征**：采用 `所处行业类别` 作**分类特征（含"未知"类）**；若用树模型可直接入，若用线性模型用 one-hot/embedding。**不加"行业比例/行业均值"拼接进特征**，除非明确说明其充当行业归一化基准。

### 3.2 0 分母（比率爆炸）

- **R3-5 识别**：比率字段出现 `abs(值) > 1e4` 的观测即疑似分母趋零（T4，如 `ASSET_LIAB_RATIO` max≈49.9 万、`ROE` min≈-1.9 万）。
- **R3-6 处理**：
  1. 计算前先做**分母检查**：`分母==0` → 该比率置 NaN（进入缺失通道），严禁直接除零或截断为 0；
  2. 比率字段统一 **winsorize 到 1% / 99% 分位**（截尾），**winsorize 必须在训练集内拟合分位数**，再应用到验证/测试集；
  3. 对长尾比率可加 `log1p(值 - 分位点)` 或取符号+log 变换，视模型而定；树模型对单调变换不敏感，可只做截尾。

### 3.3 离群值

- **R3-7** 金额类 >1e12 属**真实银行业值**（T5），不是脏数据，禁止按"超限即删除"；用 R3-2 的比率/log 通道消化。
- **R3-8** `±inf` 已确认不存在（DATA.md §2.6），但预测流水线仍须防御（`np.isinf` 检查后置 NaN）。

### 3.4 缺失（结构性缺失通道）

- **R3-9 不盲目填充**：结构性缺失是行业信号（T3），默认策略：
  - 缺失率 > 98% 的字段（金融/保险专属约 25 列）**进训练前删除**（预计可删 20–25 列）；
  - 其余字段三选一（建模时统一决策并记录）：
    - a) 树模型：按 NaN 分支走，缺失即信号，无需填充；
    - b) 线性模型：填充字段中位数/众数 + **同时生成 `is_missing` 指示列**；
    - c) 轻量模型：全部删除缺失率 > 50% 字段。
- **R3-10** 缺失率 > 80% 的中类字段（如 `N_INC_DISP_TRAD_FA` 98.7%，T11）**不得进入 top 特征筛选的强证据路径**，只能作为弱线索加进特征池。
- **R3-11 特征统计（均值/分位/分布）只在训练集内计算**，并将统计器固化（pickle）后复用。

### 3.5 特征选择

- **R3-12** 任何特征选择（含"与 FLAG 相关性排序"）**只能在训练集内做**，严禁用全数据筛选（数据泄漏）。
- **R3-13** 高相关字段若处于"高缺失行业专属"（T11），须由人复核再入"强特征"名单。
- **R3-14 记录义务**：每个实验必须记录特征清单与版本（hash），便于追溯。

## 4. 数据划分与防泄漏（R4）★ 最重点

### 4.1 数据属性前提（必背）

- 无时间维度（单年份截面），**不存在"按时间切 train/test"的方法**（DATA.md §2.2）。
- **同一公司有 1–2 条观测且行间不独立（T2）** → 随机按行切分 = 同公司两条观测分居两侧 = **模型记住公司身份而非规律，严重泄漏**。
- 部分舞弊公司两条观测中仅一条 FLAG=1（DATA.md §3.2）→ **同公司的另一条观测绝不能进入训练集**（否则模型直接学到"该公司的科目形态=舞弊"）。

### 4.2 划分方法与执行规则

| 规则 | 内容 |
|---|---|
| **R4-1 最小分组单元** | **`TICKER_SYMBOL`（公司）**。任何划分必须以公司为单位，**严禁按行随机切**。 |
| **R4-2 主方案** | `GroupKFold`（或 `StratifiedGroupKFold`，sklearn）：5 折，折内组 = 公司，正样本全局只有 28 个，折内约 5–6 个正类，**禁止贪图样本量改用按行切**。 |
| **R4-3 测试集** | 如需独立测试集：按公司 `GroupShuffleSplit`，test=20%（公司在测试集里必须整组出现）；训练/验证再进行 GroupKFold。 |
| **R4-4 不泄漏清单** | ① 特征选择、量化分位、缺失填充统计、归一化/缩放、类别编码：**全部只在训练折内拟合**；② 行业映射（附件1）属外部静态信息，允许全量使用，但"用行业占比/行业均值做特征"仍需在训练折内计算；③ 任何 `groupby(TICKER) * 全表` 的统计特征**一律禁止**；④ 相关性/EDA 分析只可用于理解，不可用于固定特征集后再测同一份测试折（若做，视为模型选择的一部分，需折外重估）。 |
| **R4-5 处置同公司双观测** | 训练折内若同公司有两行：若 FLAG 相反 → **仅保留 FLAG==1 那行入训练标签**（剔除另一行），保证同公司标签唯一进入同一折；若 FLAG 相同 → 两行可都留，但**保持同一折内**。 |
| **R4-6 标签缺失行** | FLAG=NaN 行（ticker 2606132）在划分前剔除（R1-3）。 |
| **R4-7 祖先守则** | 每折的 `groups = df["TICKER_SYMBOL"]`，交叉验证函数一律显式传 `groups=`；代码 review 时第一个检查点就是 groups 是否传入。 |

### 4.3 不平衡采样（仅在训练折内）

- **R4-8** 欠采样/过采样（如 SMOTE 变体）只允许对**训练折**做；验证/测试折保持原始自然分布。
- **R4-9** SMOTE 类方法需注意对"同公司行"的过采样复制，若生成器不知分组，产生的合成样本仍与原行同一折，可接受；但**禁止跨折合成**。
- **R4-10** 评估结果一律基于**未过采样**的原始测试分布。

## 5. 建模与评估约定（R5）

### 5.1 基线（必须先跑）

- **R5-1 基线 1（多数类）**：全部预测 0 类 → 记录 `PR-AUC`、`F1`、`Recall(1)`，作为"破烂下限"，一切模型必须显著超越。
- **R5-2 基线 2（简单规则）**：如"`REVENUE_YOY` < 0 且 `ASSET_LIAB_RATIO` > 0.6 判为舞弊"之类的可解释规则，同样记录指标。
- **R5-3** 基线类脚本编号 `b01` 起（见 R7）。

### 5.2 模型候选与默认

- **R5-4 顺序**：逻辑回归（L2，nan 填充后）→ 随机森林 → LightGBM/XGBoost →（可选）逻辑回归+手工特征消融。树模型天然可处理缺失（R3-9a）；线性模型走 R3-9b。
- **R5-5 交叉验证**：`GroupKFold(5)`，全流程每折独立拟合与评估，汇总时**按折汇总指标再取均值±std**，不做行级 pool（正类太少，pool 会失真）。

### 5.3 评估指标（不平等的世界）

- **R5-6 主指标**：**PR-AUC（Precision-Recall AUC）**（对 28 正类最敏感、不受 175:1 影响）。
- **R5-7 辅指标**：正类 Recall（覆盖率）、Precision、F1、`ROC-AUC`（仅作参考）、**公司级**（R2-3）召回/误报。
- **R5-8 禁止**：以 accuracy 为判断标准（T1 下 99%+ 的 accuracy 无意义）。
- **R5-9 置信区间**：给 k 折的指标均值±1 倍 std；正类样本量小，明示"统计功效局限"。

### 5.4 阈值与业务解读

- **R5-10** 阈值选择：在 PR 曲线上取"最低 Precision 0.5 时最高 Recall"或按用户指定；报告给出 2–3 档阈值（保守/均衡/激进）的混淆矩阵。
- **R5-11 可解释输出**：对命中样本输出 Top 特征贡献（树模型 feature importance / SHAP 可选），用于人机共审。

### 5.5 结果记录

- **R5-12** 每个实验必须产出：实验编号、特征与超参、划分 seed 与折结构、指标汇总表、结论 3 行（fits / gaps / next step）。
- **R5-13** 结果文件放 `claude_work/results/`，命名 `实验结果_<编号>.md`。

## 6. AI 协作约定（R6）

- **R6-2 只读铁律**：原始三件套（附件1/2/3）在任何情况下**只读、不修改、不覆盖、不另存变体**。AI 的全部产出写入 `claude_work/`。

### 6.2 文件与版本命名（R7 编号体系）

| 类别 | 命名模式 | 示例 |
|---|---|---|
| 探索脚本 | `explore<a>[_<purpose>].py` | `explore_fraud1.py`、`explore_fraud1b.py`（数字递增、字母后缀=同一批补充） |

| 说明文档 | `DATA.md`、`PROJECT_RULES.md`、`conclusion.md`（可复用现有文件进行增量编辑） | — |

- **R6-3 覆盖 vs 新建**：
  - **允许覆盖**：同编号脚本内部的迭代（如 `model1_baseline.py` 复跑参数）；`DATA.md`/`PROJECT_RULES.md` 的内容修正。
